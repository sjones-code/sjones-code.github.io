Concrete crack classifier

I rebuilt a published crack-detection approach with a lighter pipeline: a frozen VGG16 turns each image into 512 numbers, PCA shows how much of that is redundant, and a logistic regression makes the call.

99.5 to 99.8% accuracy across runs2,000 images, balanced~80% fewer dimensions

Pipeline

  1. Data: 1,000 crack and 1,000 non-crack images, resized to 224x224x3.
  2. Features: pre-trained VGG16 (ImageNet, no top layers, average pooling) gives a 512-d vector per image.
  3. Split: 70% train, 30% test (600 held-out images).
  4. PCA: about 101-103 components explain 95% of variance, so roughly 80% of the dimensions are redundant.
  5. Classifier: logistic regression on the 512 features.

Results

Crack style (K-Means) Test images Accuracy
Style 1 (thick, dark) 66 100%
Style 2 (jagged) 102 100%
Style 3 (hairline) 134 98.5%

Clustering the crack images into three visual styles shows where the model is weakest: fine hairline cracks. That is the failure mode I would test first on new data.

Why the numbers move between runs

Each run randomly samples 1,000 images per class and then splits them 70/30, so accuracy shifts by a few tenths of a percent depending on which images land in the test set. The confusion matrix shown is one run (597 of 600 correct). Across runs I have seen 99.5% to 99.8%, so I report a range instead of a single best result.

What this does and does not show

  • Pre-trained features transfer well: no deep network training was needed.
  • The test set comes from the same dataset. The source paper also tested on pavement, concrete buildings, and brickwork, and accuracy dropped on unseen materials. That generalization test is the next step.
  • For a robot, the same pipeline could run on a camera feed to flag anomalies.
Source: built from a graded ME 4710 homework (HW9) that re-implements ideas from a published crack-detection paper.
